# Backlog

Prioritized, highest first. Format: `N. [size] - description`.

Sizes are relative effort: XS, S, M, L, XL. They are not time estimates.

58. [S] - Style `label`: an optional user-facing name for every style, shown in the editor and as the Word name of custom styles (`body`, the headings and the TOC styles keep Word's own names), unique ignoring case and never a built-in Word name. Decided in ADR 0034.

Decided in ADR 0035, which lifts the limit of ADR 0026 on mappings written on one line.
67. [M] - Style editor, shell: a custom editor on the stylesheet file, opened with "Open With" and the command "Phrase: Edit Styles" and not by default, bound to the file like the document editor. 68. 75. [S] - Style editor, collapsible groups: every group of the panel can be collapsed, and the properties of a mark and the text of a table header row are nested groups that are closed at first. 85. 82. [L] - Word import, text content (ADR 0043): the `import-docx` package reads a DOCX and writes the document model and a report. Paragraphs, headings, lists, bold, italic and monospace as marks, hyperlinks, tracked changes as accepted, Word styles mapped to the nearest known style, and a placeholder or a report line for whatever cannot be represented. Acceptance: the imported text equals the DOCX body text paragraph by paragraph after the reported losses, checked on DOCX files built in tests and by hand on real documents. The XML parser and the small rules of the text import are in ADR 0045; tables are placeholders until the next item.
83. [M] - Word import, tables and table of contents (ADR 0043): simple tables with a header row, tables that cannot be represented flattened into their cells and reported, and a Word table of contents field turned into a `phrase-toc` block with its depth. The rules for the header row, the cells and the depth are in ADR 0046.
84. [S] - Word import, command line and VS Code (ADR 0043): `phrase import` and "Phrase: Import Word Document" write one new `.phrase.md` into a project, never over an existing file, assign IDs, and show the report like other diagnostics. The logic is `importWordDocument` in the `project` package. Decided in ADR 0047.
86. [M] - Tables with paragraphs and lists in cells, model (ADR 0048): `TableCell` holds blocks (paragraphs and lists), with one paragraph for a plain cell and none for an empty one. Core types, validation (`table-cell-block`), normalization, and a mechanical migration of every consumer of `TableCell`, with no change in behavior for plain cells. Helpers `plainCell` and `plainCellInlines` in `core`. Until the format and editor items, the serializer and the editor refuse a cell that holds more than a plain paragraph. Added at the request of the product owner.
87. [M] - Tables with paragraphs and lists in cells, format (ADR 0048): parse and write the `phrase-table` block (a bullet list of rows, each a bullet list of cells, with blocks inside), choose the form by the content (a pipe table when every cell is plain), rewrite a plain `phrase-table` to a pipe table, diagnostics (`invalid-table-body`, `table-cell-block`), and a fixture. Rows of different length are left to the document checks (`table-ragged-row`). Until the editor item, the visual editor refuses a document with a table that has such cells (`reviewText`), and offers to edit it as text.
88. [M] - Tables with paragraphs and lists in cells, DOCX (ADR 0048): paragraphs and lists inside cells, numbered from the list styles with the definitions of ADR 0010, as paragraphs in the cell. A list in a cell looks as the list style says, with the same indents as outside a table; there is no style for lists in cells. The CSS part of this item, for the editor and the paper look, moved to the editor item, since the browser cannot show such cells before the editor can.
90. [S] - Word import keeps paragraphs and lists in cells (ADR 0048): the numbered paragraphs of a cell make lists nested by their level, a heading style there is a paragraph, and a table inside a cell is joined into one paragraph of the cell and reported (`nested-table`). The code `cell-joined` is retired, and a table without a header row is written as the blocks of its cells. The list logic is shared with the body (`block-writer`).
96. [S] - The cursor can stand before and after a table that is the first or last block (gap cursor), and typing there makes a paragraph. Found when trying item 89 in VS Code; suggested and done as a fix.
97. [S] - Word import (ADR 0049): two or more line breaks in a row inside a paragraph end the paragraph, in cells and in the body; a single line break stays a space. In a list item the text after the breaks is a further paragraph of the item, and in a heading the breaks are a space. Found with a real document whose cells use double line breaks between paragraphs.
72. [S] - Style editor, theme (ADR 0050): the value of a color or font token is edited in a panel under the list (a color field with a swatch, a field for the families), and a form adds a token with a kind, a name and a value. Tokens are not renamed or removed, since styles refer to them by name.
89. [M] - Tables with paragraphs and lists in cells, editor (ADR 0048): the editor schema takes paragraphs and lists in cells (`cellBlock` group), with their commands and paste, and writes the right form on save. A paragraph of a cell takes the cell style of its table, so it has no style or ID of its own; a list in a cell has the list style. The set-style command sets the table style from a paragraph of a cell and is refused inside a list of a cell; headings, code and phrase blocks cannot be made in a cell, and a paste into a cell is reduced to paragraphs and lists (a heading or code becomes a paragraph, a table is flattened, a phrase block is left out). The CSS gives the header text to the paragraphs and list items of a header cell. `reviewText` no longer refuses such tables. The toolbar shows the table buttons anywhere in a table (`inTable`). The paper look draws only cover tables, which are plain.
